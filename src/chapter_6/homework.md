# 第六章總結與作業

## 重點回顧

- `std::cout` / `std::cerr` / `std::cin` 分別處理一般輸出、診斷輸出與標準輸入。
- `operator<<` 會格式化；`put` 和 `write` 可輸出明確的字元或位元組。
- 輸入失敗後要檢查狀態；重試前須清除旗標並丟棄不合法輸入。
- `std::stringstream` 可把字串當串流格式化或解析。
- `ifstream`、`ofstream` 與 `fstream` 分別用於讀取、寫入與讀寫檔案。
- 開啟檔案、寫入及關閉都有可能失敗；二進位資料需使用 binary 模式及明確長度。

## 作業一：安全解析設定行

實作 `bool parse_config_line(std::string_view line, int& id, int& limit)`，格式為兩個以空白分隔的整數。要求：

1. 拒絕缺欄位、非整數及多餘欄位。
2. 限制 `id > 0`、`0 <= limit <= 100000`。
3. 失敗時不修改輸出參數。
4. 至少測試有效行、空行、額外欄位、範圍錯誤及整數溢位輸入。

可先使用第五章學過的字串與參考；字串檢視需確保僅在呼叫期間使用，參見[字串與位元組轉換](../chapter_5/section_11.md)。

## 作業二：二進位複製工具

實作將來源檔案複製到目的檔案的函式。要求：

- 以固定大小緩衝區分塊讀取。
- 支援零位元組與所有可能的位元組值。
- 正確處理來源無法開啟、目的無法建立、讀取錯誤與寫入錯誤。
- 不得在目的檔案開啟失敗時宣稱成功。
- 測試空檔、小於緩衝區、恰好等於緩衝區及大於緩衝區的檔案。

## 作業三：可測試的日誌函式

延伸本章的 `write_log`：加入日期以外的一個欄位（例如序號），並撰寫單元測試驗證格式。測試需使用字串串流，避免依賴人工檢查控制台。

進階挑戰：定義多目的地輸出失敗時的回報策略，寫出一個目的地成功而另一個失敗的測試。不要忽略部分成功的情況。
