# 1.2 從程式碼到程式的生成過程

典型建置分成四個概念階段。實際工具可能把其中幾步包在同一個命令中，但理解每步的輸入和輸出，能把錯誤快速縮小到正確範圍：

1. **預處理**：讀取原始檔，展開 `#include`、`#define`、`#if` 等指令。缺少標頭或 include 路徑錯誤通常在這一步暴露。
2. **編譯**：解析 C++ 語法、名稱和型別，檢查程式是否符合語言規則，並產生組合語言或其他中間表示。分號遺漏、型別不符等通常在這一步報錯。
3. **組譯**：把組合語言轉成目標平台的機器碼，並留下符號和重定位資訊，產生物件檔。
4. **連結**：把多個物件檔和函式庫組合起來，解析各檔案使用與提供的符號，輸出程式。只有宣告、沒有任何定義的函式常在這一步報錯。

用第一節的 `main.cpp` 和 `add.cpp` 可逐階段觀察其中一個原始檔：

```sh
# 只展開標頭，觀察 main.cpp 的預處理結果
g++ -std=c++20 -E main.cpp -o main.ii

# 產生組合語言，不產生物件檔
g++ -std=c++20 -S main.cpp -o main.s

# 編譯並組譯，但不連結
g++ -std=c++20 -c main.cpp -o main.o
g++ -std=c++20 -c add.cpp -o add.o

# 將兩個物件檔連結成可執行程式
g++ main.o add.o -o app
```

執行 `app` 後應看到 `42`。如果只連結 `main.o`，連結器會抱怨找不到 `add` 的定義；這不是語法錯誤，因為 `main.cpp` 確實看過函式宣告。問題是最後提供給連結器的物件檔中沒有實作。若把 `add` 的宣告從標頭刪除，則 `main.cpp` 會在編譯階段就因為不知道 `add` 而失敗。

也可以用一個命令完成全部階段：`g++ -std=c++20 main.cpp add.cpp -o app`。大型專案常由建置系統決定哪些檔案需要重編；概念上仍是各 translation unit 分別編譯，最後再連結。

**診斷定位：** 找不到標頭先檢查檔案是否存在及 include 搜尋路徑；語法／型別錯誤看編譯器指出的原始碼行；未定義參照或重複定義則檢查送給連結器的物件檔和定義位置。開發時可啟用 `-Wall -Wextra -Wpedantic`，把常見可疑寫法轉成警告；警告仍須理解後判斷，不是每一條都代表程式一定錯。
