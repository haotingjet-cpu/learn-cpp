# 第二章總結與作業

## 重點回顧

- 宣告包括名稱、型別和初始值；型別會影響可表示範圍和運算規則。
- 花括號初始化可攔下許多可能遺失資料的窄化轉換。
- 整數除法先根據運算元型別求值；之後才轉成浮點數不會恢復小數。
- 有號溢位不可依賴繞回；浮點數不保證十進位小數能精確表示。
- 作用域決定名稱可見範圍，生命週期決定物件何時能合法使用。
- `const` 表達唯讀，`constexpr` 表達編譯期可求值，`auto` 仍會在編譯期固定型別。

## 作業一：裝置狀態資料模型

替裝置監控程式建立變數，表示裝置編號、接收封包數、最近一次量測耗時、溫度和連線狀態。宣告時都要初始化。寫程式輸出資料，並逐項說明所選型別的值域和理由。哪些欄位必須使用固定寬度型別？如果把封包數改成可能為負的數值，原本型別還合適嗎？

## 作業二：找出算術型別錯誤

預測並執行以下程式，逐行寫出除法運算的型別和結果：

```cpp
const double a{9 / 4};
const double b{9.0 / 4};
const int c{static_cast<int>(b)};
```

另寫一個 `can_add` 函式，在有號整數相加前檢查是否會超出範圍。使用 `<limits>`，測試一般正負值，以及接近最大值和最小值的輸入。

## 作業三：浮點比較政策

替量測值設計比較函式，先定義接近零時允許的絕對誤差，再定義相對於數值大小的誤差。測試一般小數、極小值、較大值、NaN 和無窮大，並說明每個案例應視為相等或不相等。

## 作業四：作用域和保留狀態

建立一個函式，宣告區域整數後輸出；在另一個函式中嘗試使用該名稱，記錄編譯器訊息並說明原因。接著加入函式區域 `static` 計數器，多呼叫幾次並描述它和普通區域變數的差異。指標、智慧指標和資源管理延伸題請等到[第五章指標與參考](../chapter_5/section_4.md)再進行。
