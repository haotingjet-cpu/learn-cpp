# 2.3 變數的算術運算

整數運算遵循整數提升與 usual arithmetic conversions。常見陷阱是運算先以較窄或無號型別完成，之後才轉成目標型別。

```cpp
int quotient = 7 / 2;       // 3：整數除法朝 0 截斷
double ratio = 7 / 2;       // 仍是 3.0
double exact = 7.0 / 2;     // 3.5
```

本例中 `quotient` 和 `ratio` 都先執行整數除法 `7 / 2`，結果是 `3`；將 `3` 存進 `double` 只會得到 `3.0`。只有把運算元之一寫成 `7.0`，除法本身才會計算出 `3.5`。遇到這類問題，先看運算式中每個運算元的型別，再看指派目標型別。

## 加法、減法與溢位

整數型別只能表示有限範圍。若有號整數運算結果超出型別範圍，程式行為未定義；不能依賴某台機器上「看起來會繞回」。無號整數則按模數回繞，但結果仍可能違反應用程式的需求。

例如用 `int` 表示接收位元組總數時，若每個封包都累加，即使單次封包大小合法，長時間運行仍可能超出上限。可在相加前驗證，不要等結果算出來才判斷。

```cpp
#include <limits>

bool can_add(int a, int b) {
    if (b > 0 && a > std::numeric_limits<int>::max() - b) {
        return false;
    }
    if (b < 0 && a < std::numeric_limits<int>::min() - b) {
        return false;
    }
    return true;
}
```

使用這個函式時，先檢查再運算：

```cpp
int total{100};
const int incoming{25};

if (can_add(total, incoming)) {
    total += incoming;
}
```

`can_add` 先用 `max - b` 或 `min - b` 判斷邊界，因此不必先執行可能溢位的 `a + b`。在大型系統中，這類檢查應集中於小型可測函式，而不是散落在每個呼叫點。

## 其他運算規則

- 對正整數除法，餘數運算子 `%` 回傳除法餘數，例如 `7 % 3` 是 `1`。
- 對負數，C++ 的整數除法朝零截斷；因此不要直接假定 `%` 一定是數學上的非負模數。
- `+=`、`++` 等複合運算仍受變數型別和值域限制，不會自動避免溢位。

位元運算符和算術運算符是不同主題；請先把數值範圍和算術行為掌握後，再看[第三章的位元運算](../chapter_3/section_3.md)。
