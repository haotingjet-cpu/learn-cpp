# 2.5 變數的作用域和生命週期

本節用三個區域解釋容易混淆的名詞：

- **作用域（scope）**：程式文字中哪裡可以使用這個名稱。
- **儲存期（storage duration）**：物件儲存空間可以存在多久。
- **生命週期（lifetime）**：物件何時已初始化、可以合法使用，到何時結束。

區域變數最常見的儲存期名稱是**自動儲存期**：程式進入宣告所在區塊時建立物件，離開該區塊時結束物件生命週期。這是在語言規則上的描述；不代表標準保證變數一定放在硬體的 stack 區域。

對初學者最重要的例子是區域變數：進入函式或區塊後執行宣告，變數開始可用；離開該區塊後，名稱不可再使用，物件生命週期也結束。

```cpp
#include <iostream>

void show_value() {
    int value{42};
    std::cout << value << '\n';
} // value 的生命週期在這裡結束

int main() {
    show_value();
    // value 在這個位置不在作用域內，不能使用。
}
```

離開區塊時，區域物件會依序結束生命週期。這項規則是 C++ 自動管理資源的重要基礎；資源管理的完整用法在[第五章模組化與指標／參考](../chapter_5/section_4.md)延伸。

- 區塊作用域的自動物件在離開區塊時結束生命週期；若建立的是類別物件，此時會呼叫解構函式。
- `static` 區域物件具有整個程式期間的儲存期，但名稱只在函式內可見；它保留前一次呼叫的狀態。
- 動態配置的物件不會只因離開目前區塊就自動結束生命週期，必須由其所有者負責釋放。直接手動配置和釋放容易造成資源洩漏或重複釋放。
- 全域物件的初始化順序跨 translation unit 不宜假設。

```cpp
#include <iostream>

int next_id() {
    static int id{0};
    ++id;
    return id;
}

int main() {
    std::cout << next_id() << '\n'; // 1
    std::cout << next_id() << '\n'; // 2
}
```

`id` 的名稱只在 `next_id` 函式中可見，但它不會在每次函式返回時消失，因為它有 `static` 儲存期。這種狀態會讓函式呼叫結果依賴前一次呼叫；使用前應確認這是設計需要，不要只為了「保留值」就任意加上 `static`。

物件生命週期結束後，即使記憶體位置看起來尚未被其他資料覆蓋，也不能繼續使用原物件。常見的懸空參考／指標錯誤會在[第五章回傳參考與指標的風險](../chapter_5/section_6.md)中以錯誤程式展示。RAII 與智慧指標也在該章的資源管理脈絡介紹，本節不要求直接使用它們。
