# 第九章總結與作業

## 重點回顧

- `std::map` 提供有序鍵值資料；只查詢時不要用會插入缺省值的 `operator[]`。
- `std::function` 儲存具指定簽章的可呼叫物件；Lambda 通常比 `bind` 更清楚。
- `std::thread` 必須安全結束；C++20 的 `std::jthread` 可協助管理生命週期。
- 共享可變狀態必須同步；資料競爭是未定義行為。
- 條件變數搭配互斥鎖與述詞使用，且可能虛假喚醒。
- 智慧指標管理生命週期，不代表執行緒安全。

## 作業一：註冊表與回呼

建立命令名稱到 handler 的 `std::map`：

1. 支援註冊、查詢及重複名稱拒絕。
2. handler 使用 Lambda，並測試空 handler。
3. 不使用 `operator[]` 做唯讀查詢。
4. 說明捕獲參考時要滿足的生命週期條件。

## 作業二：安全計數器

建立多執行緒計數器，啟動多個 worker，各自遞增固定次數。要求：

- 使用 `std::jthread` 或正確配對的 `std::thread`。
- 共享計數有同步保護。
- 程式結束時確認實際結果等於預期值。
- 比較以 mutex 保護整體狀態與使用 atomic 計數的差異。

## 作業三：程序內訊息佇列

完成本章訊息伺服器骨架，至少支援一個 producer 與一個 worker。定義停止時是排空還是丟棄佇列，並測試該行為。測試不得依賴固定延遲來猜工作完成。

進階挑戰：支援多個 worker，限制佇列最大容量，滿載時拒絕或阻塞提交者；所有策略都需有文件化的錯誤回報與停止行為。此作業不要求建立網路伺服器。
