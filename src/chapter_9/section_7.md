# 多執行緒程式設計概述

併發是多個工作在一段時間內交錯推進；平行則表示工作同時在多個執行資源上執行。程式能建立多個執行緒，不代表它一定更快；排程、同步、記憶體頻寬與工作粒度都會影響效能。

## 資料競爭與未定義行為

多執行緒同時存取同一記憶體位置，至少一方寫入，且沒有符合規則的同步，就可能形成資料競爭。C++ 資料競爭屬於未定義行為；不是單純「偶爾讀到舊值」。

```cpp
int shared_count = 0;
// 若兩個執行緒同時執行 ++shared_count，會有資料競爭
```

基本整數遞增不是原子操作。互斥鎖或原子型別各有用途；本章先以互斥鎖保護複合共享狀態。

## 執行緒設計問題

啟動執行緒前先回答：

1. 執行緒由誰擁有、由誰負責結束與等待？
2. 哪些資料被共享，哪些資料只屬於單一執行緒？
3. 共享狀態由哪把鎖保護？
4. 工作失敗如何通知呼叫端？
5. 程式關閉時如何停止並排空工作？

不要先寫一個永不停止的背景迴圈，再事後補上終止邏輯。下一節先處理執行緒建立與加入，再談共享狀態。
