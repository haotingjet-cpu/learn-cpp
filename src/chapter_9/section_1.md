# `map`、陣列、鏈結串列與樹

不同資料結構提供不同的存取特性。選擇容器應由操作需求決定，而不是只比較名稱。

`std::map` 的一般寫法是 `std::map<鍵型別, 值型別> 名稱;`。例如 `std::map<int, std::string>` 表示整數鍵對應字串值；尖括號中的型別在編譯期確定，冒號、逗號與變數名稱則是一般 C++ 宣告語法。需先包含 `<map>` 及鍵、值型別所需的標頭。

| 結構 | 典型特性 | 適合情境 |
|---|---|---|
| 固定陣列／`std::array` | 連續、大小固定 | 編譯期已知元素數 |
| `std::vector` | 連續、可增長、隨機索引 | 大部分順序資料 |
| 鏈結串列 | 節點分散，插刪需節點位置 | 特殊穩定迭代器需求；一般應先量測 |
| `std::map` | 按鍵排序，查找/插入/刪除為對數複雜度 | 有序鍵值查詢 |
| `std::unordered_map` | 雜湊查找平均常數複雜度，最差線性 | 不要求鍵排序且雜湊適用 |

`std::map<Key, Value>` 通常以平衡搜尋樹實作，但標準保證的是行為與複雜度，不是特定節點布局或一定使用某種樹。不要把標準容器內部記憶體當 ABI。

## 最小 `map` 例子

```cpp
#include <map>
#include <string>

int main() {
    std::map<int, std::string> devices;
    devices.emplace(17, "gateway");
    devices.emplace(24, "sensor");

    const auto it = devices.find(17);
    if (it != devices.end()) {
        // it->first 是鍵 17，it->second 是 "gateway"
    }
}
```

`map` 的鍵唯一並依比較器排序。插入兩次相同鍵不會自動覆寫原值；操作結果需檢查。常用增刪改查見[下一節](section_2.md)。

## 與陣列和鏈結串列比較

連續容器通常有更好的快取區域性，對掃描與索引很有利。鏈結串列雖可在已取得節點位置後快速插除，但搜尋位置仍需遍歷，且每節點配置會增加記憶體與快取成本。不能只看到「插入 O(1)」就推導鏈結串列一定更快。
