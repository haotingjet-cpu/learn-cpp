# 第五章總結與作業

每一題都要從呼叫端寫起：呼叫者傳入什麼、函式能否修改資料、失敗怎麼表示，以及回傳資料由誰擁有。這些問題比單純把程式拆成多個檔案更能檢驗模組化設計。

## 重點回顧

- 依大小與所有權需求選擇值、`const T&`、`T&`、指標或 view。
- 回傳值通常是安全且有效率的預設；參考和指標回傳要有明確生命週期保證。
- `std::span`、`std::string_view` 不擁有資料，不能延長來源生命週期。
- 多檔案程式由標頭宣告和單一 `.cpp` 定義組合，並遵守 ODR。
- 模組化要封裝狀態、錯誤策略和測試，而不只是拆檔。

## 作業一：無狀態轉換模組

完成 Base16 函式庫的標頭、實作與測試，提供錯誤位置回報。沿用[5.12 函式庫介面](section_12.md)的位元組型別。驗證所有單位元組值，再以 sanitizer 執行非法輸入和邊界案例；記錄建置旗標和檢查到的問題。

## 作業二：安全容器介面

設計一個函式，計算 `std::span<const std::byte>` 的摘要或統計值。說明 view 的生命週期前提、是否允許空 span，以及大輸入的溢位／資源政策。

## 作業三：依賴與 ODR

建立兩個以上 translation unit 的小型專案，展示標頭保護和單一定義。刻意製造重複定義錯誤，閱讀連結器診斷後修正；再移除全域可變狀態，改用物件明確傳遞依賴。建置階段回顧見[第一章](../chapter_1/section_2.md)。

## 延伸專題

將 Base16 API 包裝成命令列工具，支援編碼、解碼、標準輸入輸出、錯誤退出碼和最大輸入長度。不得透過 shell 拼接外部命令，也不得把任意 binary 輸出假設為 UTF-8。
