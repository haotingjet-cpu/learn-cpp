# 第四章總結與作業

完成每一題時，請附上至少三筆手算案例和一份實際執行輸出。邊界案例要先列出預期結果，避免只以「程式沒有崩潰」當成正確。

## 重點回顧

- `for` 適合有明確步進的迭代；`while` 適合等待狀態／輸入變化。
- 固定大小資料可用 `std::array`，動態連續資料通常用 `std::vector`。
- `reserve` 改容量不改大小；可能重新配置的操作會使參考與 iterator 失效。
- `push_back` 加入既有物件，`emplace_back` 以參數建構；效能需量測。
- Base16 每位元組輸出兩個十六進位字元；解碼必須處理格式錯誤。

## 作業一：健壯的資料掃描

讀入整數序列，計算最小值、最大值、平均數及符合門檻的項目。處理空輸入、串流錯誤和整數總和溢位；說明你選擇的累計型別與溢位政策。輸入至少測試空檔、單一值、負值和極大值。

## 作業二：Base16 函式庫

整理 `encode_hex`／`decode_hex` 為獨立介面。加入輸出長度上限、非法輸入位置回報（可改用 `std::expected`，需 C++23，或自訂結果型別）與完整邊界測試。

固定測試向量至少包含空輸入、`00`、`0f`、`10`、`7f`、`80` 和 `ff`。說明採用的大小寫與空白策略，並把「格式錯誤」和「輸入超出資源上限」分開回報。

## 作業三：容器失效實驗

保存 vector 元素參考後觸發可能重新配置，說明為何不可使用舊參考。使用 sanitizer 測試有問題的版本，再修正為安全的索引／迭代方式。

## 作業四：安全命令選單

將 Mini Shell 改成以 `std::filesystem` 列出指定目錄內容，只接受固定指令和受驗證路徑；不得把使用者輸入交給 `std::system`。

至少測試目錄不存在、權限不足、空目錄、檔名含空白和未知指令。對符號連結和允許的根目錄定義政策，不要只用字串前綴判斷路徑是否安全。
