# 複製賦值與移動賦值運算子

建構新物件與替既有物件賦值是不同操作：

```cpp
ByteString first{"one"};
ByteString second = first; // 複製建構
second = first;            // 複製賦值
second = std::move(first); // 移動賦值路徑
```

若類別自訂了資源管理行為，複製建構子、複製賦值、移動建構子、移動賦值與解構子要一起檢查。忽略其中一個，可能造成淺複製、洩漏或移動來源狀態錯誤。

賦值運算子的常見宣告格式是：

```cpp
類別名稱& operator=(參數型別 參數名稱);
```

`operator=` 是為 `=` 運算子定義行為的函式名稱；左側物件是隱含的目前物件，右側資料由參數傳入。回傳 `類別名稱&` 會回傳左側物件本身的參考，能保留一般賦值的鏈式使用方式。此處 `ByteString` 使用值參數接收右側資料，值傳遞與參考的差異見[第五章](../chapter_5/section_2.md)。

## 值傳遞與交換慣用法

上一節的 `operator=(ByteString other)` 對左值建立一份參數複本，對右值移動參數，之後以 `swap` 交換。這使複製失敗不會部分覆寫原物件，也自然處理自我賦值。

```cpp
ByteString& operator=(ByteString other) {
    swap(other);
    return *this;
}
```

參數物件離開函式時會解構，並釋放被交換到參數中的舊資源。對很多型別而言，這是簡潔可靠的作法；若複製成本極高，可考慮分開的複製／移動賦值實作並測量。

## 常見錯誤

- 先 `delete[] data_`，再嘗試從 `other.data_` 複製；自我賦值時來源已被破壞。
- `delete` 和 `new[]` 配對錯誤。
- 移動賦值沒有先處理目的物件原有資源。
- 把移動來源當成仍保有原內容。
- 為了讓容器移動而標示 `noexcept`，但實際移動可能拋出例外。

一般應遵守 Rule of Zero：將資源放進 `std::string`、`std::vector` 或智慧指標等 RAII 成員，讓編譯器產生正確的特殊成員函式，避免自行維護裸資源。
