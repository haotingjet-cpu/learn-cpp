# 第八章總結與作業

## 重點回顧

- 複製應定義新物件是否共享資源；擁有資源的裸指標不能安全地任意淺複製。
- 移動通常轉移資源所有權；`std::move` 本身不搬移資料。
- Rule of Zero 優先：用標準 RAII 型別管理資源，少寫特殊成員函式。
- `std::unique_ptr` 表達單一擁有權，離開作用域時自動釋放。
- 智慧指標管理生命週期，但不會自動解決資料競爭或業務錯誤。

## 作業一：擁有資源的型別

閱讀 `ByteString` 範例，補上：

1. 空內容處理與長度上限檢查。
2. `operator==`，比較位元組長度與內容。
3. 測試複製後兩物件彼此獨立。
4. 測試由移動後物件繼續賦值與解構。

進階：使用 `std::vector<unsigned char>` 重新設計此型別，遵守 Rule of Zero，與手動配置版本比較程式碼複雜度。

## 作業二：唯一擁有權

使用 `std::unique_ptr` 管理一組多型輸出 sink。要求 Logger 唯一擁有 sink；驗證不同 sink 可在建構時注入，且 sink 會在 Logger 銷毀時釋放。

## 作業三：追查所有權錯誤

找出以下各類程式碼的風險，並提出最小修正：

- 擁有裸指標的預設複製。
- `new[]` 配上 `delete`。
- 已移動物件仍被假設持有原資料。
- Logger 保存的參考指向已離開作用域的 sink。
- 兩個執行緒同時呼叫同一 sink，卻誤以為 `unique_ptr` 代表執行緒安全。
